## iframe 小規模PoC

再現スクリプト：[scripts/chapter-2-embed-poc.mjs](../../../../scripts/chapter-2-embed-poc.mjs)。別の一時HTTPサーバーにGemini iframeを1個置き、新規の未ログインChromium/WebKitコンテキストだけで観察する。本体にiframeを追加しない。実ユーザープロファイル・メール・予定・認証情報を使わず、入力代行・認証・制約回避を行わない。

- HTTP HEADは200、`X-Frame-Options: DENY` を観測。CSPは取得した各ポリシー内の `frame-ancestors` の有無だけを結果に記録。`frame-src` は子の読み込み制約で、埋め込み許可と解釈しない。
- WebKit 27.2 は応答200とXFO DENYによる表示拒否を観測し BLOCKED。Chromium 156.0.8078.4 はプロキシ証明書を信頼できず ERR_CERT_AUTHORITY_INVALID となり、表示可否は UNKNOWN（TLS検証は無効化しない）。ブラウザの表示と拒否ログは [embed-result.json](embed-result.json)。ヘッダー観測・実表示・ログイン互換性・端末差を区別する。
- 認証フローの互換性、ログイン済み挙動は NOT_TESTED。実機iPhone/Android、Chrome/Edge製品実機の差も NOT_TESTED。未ログインengineでの拒否から認証後の結果を断定しない。
- 採用：標準分割／別ウィンドウ／別タブ。サイト側では外部のXFO/CSPを制御できず、ヘッダーや認証の変化に依存するiframeは保守性にも問題があるため正式導線にしない。拒否はPoCの正式な結果で、本体の開発を止めない。
