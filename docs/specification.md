# v0.1 仕様

正本：[Issue #1](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/1)。2026-10-22更新の全10章・第1章先行方針を採用。

## アーキテクチャ

React + TypeScript + Vite。ルーティングはhashでホーム、一覧、各章を切り替える。追加ライブラリによるルーターや状態管理は導入しない。教材型LessonにID、番号、章題、実践課題、学習目標、説明、手順、プロンプト、理解チェック、参考URL、情報確認状況、利用条件、注意事項、公開状態を分離して保持する。

第1章は画面確認、モデル・モード確認、機能探索、練習、理解度チェック、完了チェックを提供。準備中の章は概要と条件・参考リンクだけ表示する。理解チェックは選択直後に説明し、完了記録とは独立する。

## 永続化と障害時

localStorageキー `gemini-toranomaki:progress:v1` に完了教材IDを保存。復元時は公開中のIDだけ受け入れ、重複を除く。JSON破損、ストレージ拒否・容量不足は例外を捕捉し画面内の操作を継続。初期化は確認後にキーを削除。削除成否と画面内のリセットを区別し、削除失敗時は再読み込みで古い進捗が復活する可能性を通知する。画面内の一時的な進捗操作は継続できる。保存できない場合はその旨を表示。端末間同期はない。テーマはOS設定を初期値とし、画面内で切り替え可能（永続化しない）。

Clipboard API失敗時は手動コピーを案内し、成功と区別。全文は折りたたみで表示。キーボード、ネイティブdetails、ラベル付き入力、フォーカス枠、本文スキップ、画面遷移時の見出しフォーカス、aria-live通知を採用。最小44px操作領域を確保。本文スキップはリンクの既定のhash更新を抑止し、main要素へフォーカスを移す。現在のルート・履歴は変更しない。旧 `#main` URLは元の章を復元できないため `history.replaceState` で `#home` に正規化し、初回アクセスとhash変更の両方で処理する。

## 正確性と制約

v0.1着手時の公式ヘルプ本文取得は403だった。第1章と準備中の章は現行仕様の検証が未完了で、画面にも未確認を明示する。第2章の参照確認は後述の追加仕様を参照。モデル名・価格・利用枠を固定せず、ユーザーの画面と公式情報で確認する手順を提供。非公式教材でありGoogleの製品ではない。章題はIssueの教材編成上の仮称。

## 非対象

第7〜10章本文、Gemini API、認証、DB、バックエンド、自動操作、Gemini埋め込み、Googleサービスへのアクセス、メール・予定・カメラ情報の取得。実機iPhone Safari確認は別途。第1章ではサービス連携の権限を要求しない。

## 配信

`/gemini-toranomaki/` の静的配信。PagesのSourceはGitHub Actions設定済み。PRでは `.github/workflows/ci.yml` の検証のみ実行する。同ファイルを `workflow_call` でも利用可能にし、main限定のPagesワークフローから `validate` jobとして呼ぶ。`npm ci`、型チェック、lint、単体テスト、production build、ChromiumとWebKitの全E2Eを順に必須とし、全成功後だけ検証したdistを `validated-site` アーティファクトにする。Pagesの `build` は `needs: validate` でその成果物だけをPages形式へ渡し、`deploy` は `needs: build` で公開する。失敗・スキップ・キャンセルからのデプロイ続行条件は設けない。検証内容の重複定義、独立main CI、workflow_runによる循環依存を避ける。contents権限はread、pages/id-tokenのwriteはdeployだけ。PRとmain以外での手動実行は公開しない。mainへのマージと公開は今回実行しない。

### 教材と実機能の境界

- 全資料は「教材用の模擬資料・実在しません」と表示する。テーマ名は実世界の話題だが、値・地域・発行主体・論文・レポートは架空。全国の実統計や既存論文を模倣した引用識別子/実在URLは使わない。PDF等の形式は教材上の分類で、実ファイルを配布/アップロードする操作ではない。
- 出典の正しさは形式の点数でなく、いまの主張と本文の関係で判断。企業の自社試験という一次情報と他社優位の証明、公的な古い記録と現在値、関連と因果、台数と割合、標本と全国の区別を理由付きで返す。レポート5問題も原文/節へ戻れる。
- 第4章は選択した資料だけを参照対象にする。質問例に必要な引用先が除外されていれば回答・判定を保留する。取り違え/記載なしは意図的な誤回答例として表示し、正解扱いしない。資料外の未来予測は答えられないと表示する。
- ガイド12条件は説明の水準・本文構造・原文/詳細の量が変わる固定例。除外資料をガイド/台本/マップの根拠へ混ぜない。改善済みレポート自体も二次資料なので元資料の照合が必要と説明。音声は構成と会話台本だけで、audio要素や偽の再生ボタンは置かない。マップは少数のネイティブbuttonと階層線で描く安定した木構造。
- 実操作は任意の別タブ。調査依頼文は条件に応じ全文コピーでき、まず計画だけを要求して別の開始指示を待たせる。Googleのログイン/契約、OAuth、API、実アカウント情報、個人文章入力、ファイル送信を導入しない。

出典判断は「採用（本文が主張を支える範囲）」「保留（不足情報を追加確認）」「不採用（本文と主張が不一致）」の3つ。出所不明の97%は原資料・分母・方法の不足で保留し、確認前には引用しない。原資料を追えなければ採用を見送る。企業の自社試験発表は狭い確認に採用、古い別地域資料は現在値の主張には不採用。更新前の出典回答は削除せず、新しい正答に照合し直すため、旧回答のままでは引継げない。

- 体験4は未回答/全問回答/連続採点/やり直しの4課題。予想→条件セット→自分で採点/やり直し→実操作との比較。操作なしで観察結果を表示せず、連続は2回、やり直しは採点後のリセットが必要。予想との一致は修正合格の自動認定ではなく、初期版の不具合を観察した場合は未修正と理由を示す。理解チェックと章完了も別。
- 任意演習の作成/修正/確認手順を全文コピー。実Googleのアプリ/生成物/入力は教材へ取り込まない。第4章とは資料を問いへ変える考え方で接続し、データ転送や前章完了は必須にしない。

### 保存・一時データ・非同期

- 新規キーは `gemini-toranomaki:canvas:v1` のみ。固定テーマ/対象者/表示/ステップ/版/修正選択と反映/OS/指示種類、汎用の理解チェック、テーマ/版を含む固定操作ID履歴、固定本文版のコピーID、任意操作自己申告をホワイトリスト保存。
- クイズ回答/採点結果/連続回数/予想/準備中の確認/現在の検証結果は保存しない。章離脱/再読込で初期化し、過去の操作履歴を復元しても現在の採点や修正完了の証拠にしない。この一時化は、学習履歴の保存と、現在の動作確認を混同しないための採用方針で、再回答が必要になるトレードオフを画面に明記する。
- 作成/修正/確認本文とコピーIDを一対一に対応。修正選択は修正本文だけに影響し、作成/確認本文のIDには含めない。固定文章/問題を改訂する場合は本文版も上げる。表示中の本文IDの実変更は同期invalidate。mounted/version/hashと最新の本文IDの一致を確認し、成功は最新記録にマージ。初期化/章離脱/本文変更後の旧Promise成功/失敗/finallyは状態や新コピーを変更しない。OS書込みは取り消さない。
- 既存章完了キーv1にchapter-6の許可だけを追加し1〜5章を保持。章6個別初期化は範囲説明と確認後、章6専用キー/一時状態/章6完了のみ。他章・ラボ・探索は触らず、全体初期化は従来どおり章完了だけ。読み書き/削除拒否・容量不足・不正JSONでも画面内で継続でき、未永続化と旧記録復帰の可能性を通知する。

### 検証の境界

型/lint/単体/build/Chromium/WebKit/diff-check、自己レビューと代表画面はLOG/PRに実結果を記録。点数は2テーマの未回答を含む全64組合せを単体で照合し、E2Eは実入力/採点/版比較/解除/復元/コピー競合/狭幅/両テーマ/キーボードを検証する。任意HTML/JavaScriptの実行、eval、外部スクリプト、バックエンド、OAuth/API、外部送信は実装しない。

実機iPhone Safari/Android、スクリーンリーダー、実Google Canvasの生成/保存/公開/共有、個別アカウントの提供、OS実クリップボード、教育効果は未検証。WebKit自動試験と実機は区別。自己レビューは独立レビューと呼ばない。
