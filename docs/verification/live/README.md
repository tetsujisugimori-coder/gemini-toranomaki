## 作者の自己レビュー

独立レビューではない。公式本文との対応、模擬と実アプリの境界、表示と可視情報、保存の影響範囲、コピー競合、旧章への差分を作者が確認した。

| 指摘/確認 | 対応・結果 |
| --- | --- |
| SVGのdescをaria-labelledbyへ含めると、説明が名前になりアクセシブルな説明が空になる | E2Eで検出。titleを名前、descをaria-describedbyで説明に分離。見えない正解を説明へ入れない検査を維持 |
| 任意演習で公式説明が2か所に重複 | 同じ内容を2度描画しないよう、その体験では端末別の案内だけに整理 |
| 新規テストの暗黙label取得がoption本文まで含み一致しない | アクセシブルなcomboboxの名前で特定する指定へ修正。元の値・内容・理由・focusのアサーションは維持 |
| TypeScriptが異なる固定文字列リテラル同士の直接比較を拒否 | 同じ「誤答と確認例が異なる」意図のexpect/not.toBeへ修正。型検査失敗時はbuild/E2Eへ進めない |
| 現在の確認と過去履歴が混ざらないか | 題材/映像/共有目的の変更で該当チェックを解除。履歴を現在の正答に使わない。条件変更後と再読込をE2Eで確認 |
| コピーと別操作が競合しないか | 本文版ID、latest stateへのマージ、mounted/version/hash、初期化時同期invalidateを確認。古い成功/失敗と新コピー待機、同一ターンreset/hashを検証 |
| 既存記録/Pages/依存への影響 | 章完了の許可IDと導線だけ追加。旧5キーを維持。既存230 E2Eを削除せず、公開ゲート/依存/lockfileを変更しない |

テストの件数・最終結果はLOG/PRに記録する。初回の失敗を成功として扱わず、SVG修正とテスト指定の修正後に最新production buildで再実行する。
