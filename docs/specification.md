# v0.1 仕様

正本：[Issue #1](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/1)。2026-10-22更新の全10章・第1章先行方針を採用。

## アーキテクチャ

React + TypeScript + Vite。ルーティングはhashでホーム、一覧、各章を切り替える。追加ライブラリによるルーターや状態管理は導入しない。教材型LessonにID、番号、章題、実践課題、学習目標、説明、手順、プロンプト、理解チェック、参考URL、情報確認状況、利用条件、注意事項、公開状態を分離して保持する。

第1章は画面確認、モデル・モード確認、機能探索、練習、理解度チェック、完了チェックを提供。準備中の章は概要と条件・参考リンクだけ表示する。理解チェックは選択直後に説明し、完了記録とは独立する。

## 永続化と障害時

localStorageキー `gemini-toranomaki:progress:v1` に完了教材IDを保存。復元時は公開中のIDだけ受け入れ、重複を除く。JSON破損、ストレージ拒否・容量不足は例外を捕捉し画面内の操作を継続。初期化は確認後にキーを削除。削除成否と画面内のリセットを区別し、削除失敗時は再読み込みで古い進捗が復活する可能性を通知する。画面内の一時的な進捗操作は継続できる。保存できない場合はその旨を表示。端末間同期はない。テーマはOS設定を初期値とし、画面内で切り替え可能（永続化しない）。

Clipboard API失敗時は手動コピーを案内し、成功と区別。全文は折りたたみで表示。キーボード、ネイティブdetails、ラベル付き入力、フォーカス枠、本文スキップ、画面遷移時の見出しフォーカス、aria-live通知を採用。最小44px操作領域を確保。本文スキップはリンクの既定のhash更新を抑止し、main要素へフォーカスを移す。現在のルート・履歴は変更しない。旧 `#main` URLは元の章を復元できないため `history.replaceState` で `#home` に正規化し、初回アクセスとhash変更の両方で処理する。

## 正確性と制約

v0.1着手時の公式ヘルプ本文取得は403だった。第1章と準備中の章は現行仕様の検証が未完了で、画面にも未確認を明示する。第2章の参照確認は後述の追加仕様を参照。モデル名・価格・利用枠を固定せず、ユーザーの画面と公式情報で確認する手順を提供。非公式教材でありGoogleの製品ではない。章題はIssueの教材編成上の仮称。

## 非対象

第3〜10章本文、Gemini API、認証、DB、バックエンド、自動操作、Gemini埋め込み、Googleサービスへのアクセス、メール・予定・カメラ情報の取得。実機iPhone Safari確認は別途。第1章ではサービス連携の権限を要求しない。

## 配信

`/gemini-toranomaki/` の静的配信。PagesのSourceはGitHub Actions設定済み。PRでは `.github/workflows/ci.yml` の検証のみ実行する。同ファイルを `workflow_call` でも利用可能にし、main限定のPagesワークフローから `validate` jobとして呼ぶ。`npm ci`、型チェック、lint、単体テスト、production build、ChromiumとWebKitの全E2Eを順に必須とし、全成功後だけ検証したdistを `validated-site` アーティファクトにする。Pagesの `build` は `needs: validate` でその成果物だけをPages形式へ渡し、`deploy` は `needs: build` で公開する。失敗・スキップ・キャンセルからのデプロイ続行条件は設けない。検証内容の重複定義、独立main CI、workflow_runによる循環依存を避ける。contents権限はread、pages/id-tokenのwriteはdeployだけ。PRとmain以外での手動実行は公開しない。mainへのマージと公開は今回実行しない。

# v0.2 追加仕様：Gemini体験ラボ

既存main 2426b2dとIssue #1／マージ済みPR #2を確認。章番号・章題・課題、既存の進捗キー、スキップリンク、初期化通知、Pagesの公開ゲートは維持する。独立イントロは `#lab`、4体験は `#lab-ask` / `#lab-rewrite` / `#lab-image` / `#lab-quiz`。完了による移動制限は設けない。

`lab-data.ts` は教材・固定理解チェック、`lab-prompts.ts` は純粋な生成関数、`Lab.tsx` は共通UI、`lab-storage.ts` は進捗を担当する。既存の章教材と分離し、追加ライブラリや汎用教材フレームワークは導入しない。

ラボの記録キーは `gemini-toranomaki:lab:v1`。各体験にコピー成功、Gemini実行の自己申告、応用の自己申告、固定チェックの最終回答番号を記録。操作成功はコピーAPI成功時だけ記録し、実行・理解を自動認定しない。理解は正解保証ではなく、確認課題の最終結果と自己申告を別表示する。旧章データは読み書きしない。保存拒否・破損を処理し、メモリ内で継続する。既存「進捗を初期化」は従来どおり章進捗のみを対象とする。ラボの自己申告はチェックを外して訂正でき、固定課題は再回答できる。

自由入力、設定変更内容、比較用指示、予想、生成回答、振り返りは永続化しない。Geminiへの自動送信・APIアクセスも行わない。コピーと外部タブ操作は学習者が行う。体験を離れると入力は消える。元の設定への復帰は設定のみを初期化し、比較用指示と学習記録は維持する。共通安全チェックは回答直後に理由を表示し、回答は保存しない。

既存余白・テーマを使い、ネイティブinput/select/textarea/details、ラベル、グループ化したラジオ、aria-live、フォーカス表示、狭幅で縦積みの比較を採用する。予想・条件変更・比較・解説・応用の順を表示するが、段階はロックせず再挑戦可能にする。

## 第2章：Googleサービス連携（Issue #6）

初回依頼は [Issue #6](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/6) と [保存した本文](requests/issue-6.md)。Issue本文は編集しない。既存10章の番号・章題・実践課題、hashルーティング、Pagesワークフローを維持。第1章の次に `#chapter-2` を学習可能とし、ナビ・一覧・機能探検から移動する。追加依存なし。

- 教材データ、指示生成、章2の保存、React UIを4ファイルに分離。4体験はボタンと前後移動で自由に往復でき、位置を保存する。体験切替時に見出しへフォーカス。受信箱は選択ボタンとライブ通知、比較はラベル付きの予定カードを使い、狭幅では縦積み。新規アニメーションなし。
- メール3通はすべて架空（`.invalid` 送信元）。10月18日の初回案内、10月22日の明示的訂正、より新しい無関係な10月23日のお知らせ。正答は10月31日15:00〜16:30、Asia/Tokyo（UTC+09:00）、架空ひろばB室。送信日とは別。7項目の選択と採用判断に即時理由を返す。
- 模擬の検索指示には3通の本文を含め、実Gmailへの検索を禁止。検索対象・送信期間・出典の詳細度・不明点表示を選べる。基本の日時・出典・登録停止条件は外せない。実アカウント指示には架空メールを混ぜず、非機密の自分の案内だけを扱い、未発見なら止める。
- 検索指示は作成・変更・削除を禁止。登録用指示は別に表示する。模擬では正しい比較ケースで7項目を照合して明示的に進んだ今回の状態だけで解放し、指示自体も実登録は禁止。曖昧な時刻、旧案内、重複ケースでは進めず理由を返す。ケース変更・チェック変更で解放を取り消す。任意の実操作では7項目の自己申告後、第2段階Aとして対象1件の全項目提示だけを依頼する。この段階では作成・変更・削除を一切禁止する。第2段階BはGeminiから提示された1件を原文と照合した自己申告後に表示し、確認用ID、イベント名、開催日、開始/終了、時間帯、場所、訂正情報、対象カレンダーと所有者/アカウント、重複確認をGemini側だけで記入するひな形とする。提示後の別メッセージによる最終承認、全項目一致、1件の一意な特定が成立する場合だけ新規作成を依頼する。未記入・複数候補・対象不明・不足・不一致・矛盾・未確認・重複は停止。内容変更時は再提示と新しい別メッセージの承認を求める。既存予定の変更/削除は承認しない。教材は実データを入力/保存せず、チェックも承認成立を検証しない。確認・設定の変更と保留で最終照合の自己申告を解除する。
- コピーAPI成功だけを種類別の履歴に記録。失敗時は表示済み全文で手動コピーを案内し、成功扱いしない。非同期コピー完了後の保存は最新状態にマージし、章から離れた後や指示の条件変更後の遅い完了は無視する。登録保留でも既存のバージョンを更新し、古い成功/失敗の通知・記録・finallyを無効化する。待機フラグを解除し、再確認後のコピーを許可する。新しいコピー待機中に古い結果が届いてもその待機状態を変えない。これは教材内の扱いで、開始済みのOSクリップボードへの書き込みを取り消すことはできない。
- 既存 `gemini-toranomaki:progress:v1` はそのまま使い、公開IDのchapter-1/2だけを復元。各章の切替は他章のIDを維持する。旧chapter-1データを変換する必要はない。ラボ・探索キーは変更しない。
- `gemini-toranomaki:services:v1` は体験位置、選択した架空メール、固定問題・抽出の選択番号、比較ケース、模擬確認の完了履歴、種類別コピー履歴、Gemini検索とGoogleカレンダー確認の自己申告をホワイトリストで保存。任意の実メール本文やAI回答を入力・保存しない。確認チェック・全項目一致の自己申告・登録指示の解放状態は保存しない。コピー履歴は旧real-registrationを残し、新たにreal-preflightとreal-executionを追加する。キーや旧データは変換しない。保存拒否・破損時は通知し画面内で続行。「進捗を初期化」は章の完了のみを消し、ラボ・探索・章2の操作履歴には影響しない。
- 登録後の手順は、実Googleカレンダーを直接開き、アカウント、対象カレンダー、予定の実在、日時・時間帯・場所・訂正・重複を確認すること。教材は操作・登録成功を確認できず、自動で章完了にしない。任意の実操作をしなくても章完了を自己申告でき、いつでも解除できる。

### PR #7 レビュー修正の範囲と限界

任意実アカウント演習だけに第1章と同じ「Geminiを開く ↗（別タブ）」を配置。実アカウントでのログイン・連携成功は教材が保証せず、模擬演習ではリンクを必須にしない。プロンプトは確認・照合・別メッセージによる承認を指示するが、実行先のGeminiの遵守や実データの一致を、この静的サイトから強制・検証することはできない。実演習は引き続き任意であり、学習者による原文照合とGoogleカレンダーでの直接確認が必要。
