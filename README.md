# Gemini活用 虎の巻

Gemini固有の機能とGoogleサービス連携を、操作しながら学ぶ日本語の非公式教材。React / TypeScript / Viteによる静的サイトです。[Issue #1](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/1)を仕様の正本とし、v0.1の全10章の目次と第1章に、v0.2で独立イントロ「Gemini体験ラボ」を追加しました。第2章の架空メール、第3・4章の調査と資料学習に続き、第5章ではLiveの会話・映像・共有、第6章ではクイズとタイマーの試作・修正・検証を模擬体験できます。

## セットアップ・開発

Node.js 22以上（Viteの要件：22.12以上）、npmを使用します。

```sh
npm ci --cache /tmp/gemini-npm-cache
npm run dev
```

開発サーバーでは `/gemini-toranomaki/` を開きます。ログイン、APIキー、DB、バックエンドは不要です。Gemini本体は別タブで操作します。

## テスト

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

E2Eはproduction previewを自動起動し、サブパスで遷移・コピー・理解チェック・進捗・保存失敗・375/390/1280px・テーマ・キーボードを検証します。コピー成功はブラウザAPIをモックし、渡した全文を確認します。OSの実クリップボードと実機iPhone Safariは別途確認が必要です。

## 公開

PagesのSourceは **GitHub Actions** に設定済みです。PRではCI検証だけを実行します。mainへのpush（またはmainでの手動実行）ではPagesが同じCIを再利用し、`npm ci`、型チェック、lint、単体テスト、production build、ChromiumとWebKitの全E2E成功を必須にします。検証済みのdistだけをアーティファクトとして渡し、`validate → build → deploy` の依存関係で公開します。いずれかの失敗・スキップ・キャンセル時は公開しません。PRやmain以外から本番公開しません。独立したmain用CIの二重実行やワークフロー間の完了イベント待ちはありません。デプロイjobだけに `pages: write` と `id-token: write` を付与しています。

Viteのbaseは `/gemini-toranomaki/`。画面遷移はhash方式でPagesの404を避けます。想定公開先：`https://tetsujisugimori-coder.github.io/gemini-toranomaki/`（公開確認は未実施）。

## データ・制約

教材は `src/curriculum.ts`、進捗は `src/storage.ts`、画面は `src/main.tsx`。進捗はこのブラウザだけに保存され、保存不可時はメモリ内で動作します。第1〜6章は独立して完了・解除でき、第7〜10章の完了は記録できません。初期化は確認操作後に行います。保存領域の削除に失敗した場合も画面内では初期化し、再読み込みで旧進捗が復活する可能性を通知します。本文スキップは現在の章URLや戻る履歴を変更せずフォーカスだけを移動します。旧 `#main` URLは章情報を持たないため、ホームへ置換して復旧します。

第1章と準備中の章では、初回の公式情報取得がネットワーク制限で拒否されたため、最新名称・プラン条件・UIは未確認と表示しています。それらのリンクも到達性の再確認が必要です。第2章の公式参照は2026-10-23に本文を確認しました。教材内にGoogleの公式ロゴ・画像は含みません。

詳細は [仕様](docs/specification.md)、[教材構成](docs/curriculum.md)、[実装履歴](LOG.md) を参照してください。

## v0.2：Gemini体験ラボ

ホームまたはナビの「Gemini体験ラボ」から、質問・文章・画像・クイズの4体験へ進めます。各体験は予想→操作→条件変更→比較→解説→応用を提供します。全体験の完了は不要で、いつでも既存10章へ進めます。

ラボの教材は `src/lab-data.ts`、生成ロジックは `src/lab-prompts.ts`、UIは `src/Lab.tsx`、記録は `src/lab-storage.ts`。章の既存保存キーは維持し、ラボは別キーにコピー成功・実行自己申告・応用自己申告・固定課題の最終回答のみ保存します。入力文章・生成回答・振り返りは保存も自動送信もせず、体験を離れると消えます。既存の章進捗初期化は章のみを対象とします。ラボの記録はチェックの解除や再回答で訂正できます。

ラボの公式参照（プライバシー・画像生成／編集）は2026-10-22に本文確認済み。既存10章全機能の現行仕様を確認したものではありません。ローカルとCIの検証経緯はLOG.mdを参照してください。

## 第1章：画面探検・機能探検マップ

第1章には、12か所を選べる教材用の模擬画面と、8つの目的から機能を選ぶマップがあります。機能から目的を探すこともできます。実際の送信・添付・予約・連携は行いません。モデル名と思考レベルは2026年10月22日のユーザー確認例で、現在の利用可能性を保証しません。

教材データは `src/exploration-data.ts`、UIは `src/Exploration.tsx`、探索記録は `src/exploration-storage.ts`。探索済み・実画面の課題確認は独立キーに保存し、章完了とラボの記録を維持します。「進捗を初期化」は章完了だけ、「探索記録だけを初期化」は探索だけを対象とします。

## 第2章：Googleサービス連携

初回仕様の正本は [Issue #6](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/6)（本文は変更しない）。[初回依頼の保存](docs/requests/issue-6.md)も参照。第7章以降は準備中のままです。

`#chapter-2` で、架空のGmail受信箱 → 接続の理解 → 検索指示ビルダー → 原文・AI抽出例・登録候補の比較を体験できます。訂正メールを優先する理由を考え、曖昧な時刻・重複・未発見・連携不可・原文との不一致では登録を止める判断を学びます。検索と登録の指示を分離し、模擬の登録用指示も実登録は禁止です。任意の実アカウント演習は、学習者がGeminiで操作します。実操作は検索→第2段階A（対象1件の全項目提示だけ）→Gemini側で原文照合→別メッセージによる第2段階B（最終承認・実行）に分けます。確認用IDと全項目が一致しない・未記入・候補が複数の場合は停止する指示です。記入はGemini側だけで行い、教材には実データを入力しません。任意演習内の「Geminiを開く」から別タブへ移動できます。この教材はOAuth・各種API・メール取得・予定登録を実装しません。

`services-data.ts` は架空メールと固定問題、`services-prompts.ts` は指示生成、`Services.tsx` は4体験、`services-storage.ts` は章2の独立記録を担当します。章完了の既存キーは維持し、chapter-1の旧データを復元します。章2専用キー `gemini-toranomaki:services:v1` には固定選択、現在位置、模擬確認の履歴、種類別コピー成功、任意操作の自己申告だけを保存します。実メール・AI回答は入力も保存もしません。旧コピー履歴を維持し、登録前確認と最終実行指示のコピーは別に記録します。登録用指示を表示するための今回の確認チェックと全項目一致の自己申告は保存せず、再読み込みで再確認が必要です。章完了は自分で記録し、実登録を必須にしません。

2026-10-23にGoogle公式ヘルプ4件の本文を確認しました。参照URL、現行の接続導線、提供条件、仕様判断は [仕様](docs/specification.md#第2章googleサービス連携issue-6) に記録しています。実機iPhone Safari・スクリーンリーダー・実アカウントでのGoogle連携／予定作成・OS実クリップボードは未検証です。

保留・ケース変更・確認変更・演習条件変更・章離脱後に完了した古いコピーは、教材内の通知・成功記録へ反映しません。OSクリップボードへの書き込み自体の完了は取り消せません。教材のチェックは自己申告であり、実データの一致・Googleへのログイン・実連携・最終承認の成立をシステムが検証するものではありません。

## 第3・4章：調査を検証し、Notebookで学ぶ

[Issue #8](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/8) の統合実装。第3章は調査テーマ/条件の選択、計画の前後比較、7種類の出典判断、5つのレポート誤りと改善版を扱います。第4章は資料の追加/除外、4種類の回答と引用の照合、対象・形式・詳しさで変わる学習ガイド、音声解説の台本とノード選択式マインドマップを扱います。台本には音声・再生機能はありません。

3テーマの資料はすべてオリジナルの「教材用の模擬資料」で、実在する統計・論文の代わりにはなりません。PDF/Web/テキスト等は分類を学ぶための表示です。実ファイルのアップロードは不要で、Googleへのログイン・API・送信・サービス間転送は行いません。

第3章の計画・出典・レポートを固定課題で確認すると、「この調査をNotebookで学ぶ」からテーマIDと標本集計・観察資料・改善済みレポートを引き継げます。章完了チェックは不要です。第4章は単独でも始められます。参照対象を変えると、引用・ガイド・台本・マップもその資料に合わせて変わります。引用番号の存在だけでは支持の証明にならず、取り違え・記載なし・資料外の質問も教材に含みます。

新しいキーは `gemini-toranomaki:research:v1` と `gemini-toranomaki:notebook:v1`。固定テーマ/選択/ステップ/問題回答とコピー履歴だけを保存し、個人の調査文章や実アカウント情報は保存しません。章3の検証状態には改訂IDを付け、連携元の変更・初期化・破損で古い引継ぎ資料/回答を無効化します。単独Notebookの記録には影響しません。各章の個別初期化はその章の固定記録と完了だけを対象とし、第3章由来の資料は必要に応じて無効化します。全体の進捗初期化は従来どおり完了記録だけです。保存拒否時も画面内で操作でき、永続化の失敗や再読み込みによる旧記録復活の可能性を通知します。

Google公式本文4件は2026-10-24（UTC、Issue #8作成作業時）に確認。本文は「Gemini Notebook」、ヘルプ名等には「NotebookLM」表記が残っていました。確認できた関係・条件と、教材での簡略化を [仕様](docs/specification.md#第34章調査と資料学習issue-8) に分けて記録しています。実操作は任意の別タブで、自分の画面・アカウントの提供条件を確認してください。実Google操作、実機iPhone Safari、スクリーンリーダー、OS実クリップボードは未検証です。

## 第5章：Gemini Live

[Issue #10](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/10)。章一覧・ナビ・第1章の機能探検から `#chapter-5` へ進めます。実践課題「カメラで物を見せながら質問」を維持し、会話を調整する→架空パッケージの可視情報を判断する→共有前後を確認する→任意の実アプリ演習の4体験を提供します。模擬体験だけで章完了を自己申告できます。

`Live.tsx`、`LivePackage.tsx`、`live-data.ts`、`live-storage.ts` にUI・オリジナルSVG・固定教材・専用記録を分けます。映像条件は全体/文字拡大/ぼけ/一部遮蔽の静止教材。文字による代替でも同じ判断を練習でき、正本は回答後に明示的に開きます。カメラ・マイク・画面共有の権限要求、録音/撮影/音声認識、Googleへの送信はありません。

`gemini-toranomaki:live:v1` に固定選択・現在の問題回答・過去の操作履歴・本文版IDに対応するコピー成功・任意演習の自己申告だけを保存します。実会話/画像/画面/個人情報は扱いません。条件変更は該当する現在の確認だけを解除し、別体験の記録は保持。第5章の個別初期化は確認後に第5章記録と完了だけを削除し、全体初期化は従来どおり章完了だけです。保存拒否/容量不足/破損時も画面内で続けられ、旧記録復帰の可能性を通知します。

2026-10-25 UTCにiOS/AndroidのLive、iOSモバイルアプリ、リンク先のデータ取扱説明の公式本文を確認。Safariで教材を読むことと、対応モバイルアプリでLiveを使うことは別です。実アプリ演習は任意で、リンクがLive/アプリ起動や提供を保証するものではありません。[公式確認と簡略化・未確認事項](docs/specification.md#第5章gemini-liveissue-10) を参照してください。

## 第6章：Canvas

[Issue #12](https://github.com/tetsujisugimori-coder/gemini-toranomaki/issues/12)。実践課題「簡単なWebアプリを作る」を、3問・各3択の学習クイズで体験します。章一覧・ナビ・第1章の機能探検から `#chapter-6` へ進めます。4体験は、動作の具体化→固定試作品の操作→修正依頼と前後比較→実操作での検証です。初回は具体的な不具合結果を伏せ、予想を確定→操作→観察後に理由を開きます。任意ヒントで先へ進むこともできます。体験1のタイマー工房では秒数・数字の大きさ・0秒で停止/繰り返す指示を明示反映し、前後を実操作できます。すべて固定ルールで、AI生成ではありません。

`CanvasWorkshop.tsx` と `canvas-workshop.ts` は追加タイマーの実動作/指示/判断問題を担当。`Canvas.tsx` が体験、`canvas-data.ts` がオリジナル問題/指示/OS別参考資料、`canvas-engine.ts` が回答と採点、`canvas-storage.ts` が固定記録を管理します。正答は固定データから計算し、任意のコードを入力/実行する機能はありません。AI API・OAuth・ログイン・外部通信・バックエンドは追加しません。任意のGemini演習では、作成/修正/確認手順を全文コピーできます。生成/保存/共有は実Google側で学習者が行い、公開範囲を自分で確認します。

専用キー `gemini-toranomaki:canvas:v1` は固定条件・理解チェック・過去の操作ID・本文版に対応するコピー成功・任意操作自己申告を保存。任意フィールドとして閲覧自己記録・版付きの新判断問題・タイマー固定条件/過去操作/コピーIDを追加し、旧記録はそのまま読み込みます。旧基本チェックの回答を新判断問題の達成へ流用しません。閲覧、模擬実践、判断達成、実Gemini自己申告、章完了自己申告を分けて表示します。クイズ回答/採点/現在の検証、タイマーの残秒/進行/到達回数/比較状態は一時データで、再読み込みや章離脱で消えます。初期版と修正版は回答条件を共有しますが、結果は別々に計算し、回答変更は両版の旧結果を解除。同じ条件の再選択では維持します。第6章だけの確認付き初期化と従来の全体初期化（完了だけ）を区別し、旧キーを保護します。

2026-10-25 UTCにCanvas紹介とPC/iOS/Androidの公式ヘルプ本文を確認しました。資料ごとにOS/共通を明示し、添字では分類しません。[確認内容・簡略化・保存仕様・未検証](docs/specification.md#第6章canvasissue-12) を参照してください。模擬だけでも章完了を自己申告でき、全問正解や実Google操作は必須ではありません。
