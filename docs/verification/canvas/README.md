## 作者の自己レビュー（独立レビューではない）

| 確認・発見 | 対応 |
| --- | --- |
| 説明と動作/正答が一致するか | 2テーマの全64組合せ（null/3選択×3問）を初期/未回答ガードで照合。実UIで未回答/部分/混合/全正解/全不正解/再採点/回答変更/やり直しを確認 |
| 前後比較で旧点数が別版へ流用されないか | 回答を共通化し、採点/回数は版別。回答変更で両版結果解除、修正反映変更で修正版解除。同一条件は保持。E2Eで実際に比較 |
| 「見た目のみ」で動作まで直った扱いにならないか | ボタン強調だけでは未回答採点が残る。動作修正の明示反映だけ未回答番号を検出。選択/反映済みを別表示 |
| 観察が操作なしに表示されないか | 予想→条件セット後に採点等を必要とする。連続は2回、やり直しは採点後のリセットが必要。予想一致は修正完了の認定ではない |
| 境界条件セット後に操作欄が消える | 条件セットで旧結果を解除すると、そのボタン欄も消える構成を改善。折りたたみを安定表示してフォーカス消失を避けた |
| 章初期化で一時選択も戻るか | 確認課題の選択も既定値へ戻す処理を追加し、4検証課題を試した後の章初期化をE2Eへ追加 |
| 保存と現在の検証が混ざらないか | 回答/点数/現在検証は保存しない。復元する履歴は過去と明示。保存拒否→初期化失敗→reloadでも復元するのは旧固定記録だけ |
| コピー競合 | 既存hookと本文ID/最新記録マージを再利用。作成のテーマ/対象者/結果表示、修正内容の変更、reset/離脱/同一ターン、新旧Promiseを成功/失敗で検証 |
| 既存章への影響 | 第6章導線/完了IDと準備中の対象を第7章へ移すテスト更新のみ。第1〜5章本体/保存キー/依存/lockfile/Pages条件は変更しない |

最初のlintは未使用変数/importで停止し、除去後にbuild。新規E2E初回は採点のrequestAnimationFrameによるフォーカス完了前に次の設問移動を操作し、4件が失敗した。結果見出しのフォーカスを待ってから次の操作へ進む指定へ修正し、フォーカスのアサーションを維持。修正後の新規70件は両engineで成功。最終版の全体回帰・件数・CIはLOG/PRへ記録する。

採用した保存方針のトレードオフ：回答を復元するより、現在の操作結果と過去の履歴を混同しないことを優先した。再読み込み後は再回答が必要で、画面に明示する。任意コードの実行や実Google生成は当初から範囲外で、疑似生成や静的な点数切替で代用していない。

未検証：実機iPhone Safari/Android、スクリーンリーダー、実Google Canvasの生成/保存/共有/公開、個別アカウントの提供/上限、OS実クリップボード、教育効果。独立レビューは今回未実施。WebKit自動試験を実機確認とは呼ばず、技術テスト成功を教育効果の実証としない。
