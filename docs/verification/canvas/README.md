## PR #13 P2：確定予想と観察証拠の固定（2026-10-25 UTC）

開始時の作業ツリーはクリーン。fetch後のローカル/リモート/PR HEADはすべてレビュー対象 `fc2a4f5729aaa8fe17a69a2417a56765cbbd5312` と一致し、先行変更はなかった。既存Draft PR #13の同じブランチで修正し、Issue #12の初回本文は変更しない。

原因：体験4のpreparedは課題/contextだけを保持し、比較が変更可能なpredictionを直接参照していた。「全問回答の採点」で0点を予想→条件セット→1点を観察→予想を1点へ変えると、不一致が一致へ変わる。修正前に追加した回帰はChromium/WebKit双方で、採点後も予想のラジオが有効なため失敗した（2失敗）。

採用設計：一時snapshotに課題ID・context（テーマ/対象者/結果表示/版/反映済み修正）・確定予想・セット時回答・採点実行済みを保持。条件セット時に予想を固定して入力/再セットを無効化し、比較はsnapshot内の予想を使う。観察には一致するcontext/課題/回答と実採点を要求する。回答は純粋関数で新配列へ更新するためsnapshotは変化しない。採点エンジン/正答データ/保存処理/共有コピーhookの変更は不要だった。

「予想を変更して再挑戦」は両版のgrade/countと現在比較を破棄し、予想を未選択へ戻してlegendへフォーカス。回答配列を残しても証拠にはせず、新たな条件セットが両版の結果/回数を再び消し、実操作を必須にする。確定中の説明と再挑戦の案内はrole=status、予想欄はaria-describedbyで関連付ける。

| 操作 | 現在の検証/証拠 |
| --- | --- |
| 確認課題/テーマ/対象者/結果表示/版/反映済み修正/回答の実変更 | 確定予想とsnapshotを解除。以前の条件へ戻しても復活しない。新たなセットが両版の旧結果/回数を破棄 |
| 同じ条件/同じ回答の再選択 | snapshot/確定予想/結果を保持。確定後の別予想は選択不可 |
| 同じ検証で連続採点 | 新しいセットから数え2回目に比較。過去の実行回数を使わない |
| やり直し | 通常は検証解除。やり直し課題だけは同じセットの回答で採点済みの場合に限り、回答/点数/案内の消去を観察。採点前のやり直しや、その後の空回答の再採点は旧検証を解除 |
| 再挑戦 | 両版の結果/回数/比較/確定予想を解除し、予想→セット→実操作を再度要求 |
| 章離脱/再読込/第6章個別初期化 | 一時snapshot/点数/回数/比較を消去。localStorageへの追加保存なし。他章/既存キー/全体初期化の意味は不変 |
