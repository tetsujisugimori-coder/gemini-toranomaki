# 実装依頼：第2章「Googleサービス連携」

対象：`tetsujisugimori-coder/gemini-toranomaki`
関連：Issue #1（10章の章題・実践課題の正本）、マージ済みPR #5（第1章）

## 1. 目的と教育方針
第2章「Googleサービス連携」の実践課題「Gmailから予定を探しカレンダーに登録」を、初学者向けのインタラクティブ教材として完成させる。
イントロはAIとのやり取り、第1章は画面・機能探検、第2章は**別サービスの情報を調べ、正確性を確認し、操作に移す**という違いを出す。「連携したら自動で何でもできる」と誤解させない。
実装は静的教材であり、実Gmail／Googleカレンダーへのアクセス、OAuth、Gemini API、登録代行、自動送信は行わない。

## 2. 実装する体験
### A. 予想・模擬メールの読み解き
架空のイベント案内メール群（一般案内、日時変更の訂正メール、無関係なメールなど）を表示。**古い案内と訂正情報を見分ける**ことを中心課題にする。
件名、開催日時、タイムゾーン、場所、訂正有無、送信日時を読み取り、ユーザーがクリック／選択して予定カードを組み立てる。採点は固定データに基づき理由を即時表示。メール送信日時と開催日時を混同させない。模擬メールに実在人物・私的情報を含めない。

### B. GeminiからGoogleサービスを使う準備
`gemini.google.com` のGeminiアプリからGoogle Workspaceアプリ連携を使う手順を案内。アカウント一致、アクティビティの保存、必要なGmailのスマート機能、管理者制限、権限・プライバシーを、公式の2026-10-23時点の情報に沿って説明。設定変更を学習完了の必須条件にせず、未接続の学習者もAとCの模擬演習へ進める。
「Geminiアプリのアプリ連携」と「Gmail内のGemini」は別導線として区別し、後者を補足扱いにする。プラン・地域・組織などによる差は断定しない。

### C. 検索指示→確認→登録指示の2段階実習
模擬データの結果をもとに、検索対象・期間・確認項目などを組み立てる指示文ビルダーを用意する。コピーできる指示文は状況別に明確に分ける：
- **模擬演習用**：架空のメール本文を指示文に含めて考察させる。実在のGmailにあると偽らない。
- **任意の実アカウント用**：自分に届いている非機密の案内に限り、GeminiへGmailの検索を依頼する。メール未発見時はそこで止める。
カレンダー作成は検索回答の出典・最新版・日時・タイムゾーン・重複有無を学習者が確認してから、**別の明示的な指示**で実施する流れにする。教材側の「登録」風ボタンが実登録を行うように見せない。登録後はGoogleカレンダーを直接開き、実在・日付・時間帯・対象カレンダー・二重登録を確認する。初回の実習では実登録自体を必須にしない。

### D. 比較と判断・トラブル分岐
メール→抽出された予定→予定カードというBefore/Afterを見比べるUI。曖昧な時刻、古い訂正前の案内、二重登録、連携不可、メール未発見、必要事項欠落を扱い、「登録せず追加確認」を正答として選べるようにする。AIの回答を無条件に信用しないことが到達目標。
章末に理解チェック（固定問題、選択直後の理由説明、再回答可）と実行の自己申告を設ける。模擬操作、コピー成功、実Geminiでの操作、実予定作成は状態・文言を混同しない。
