Prepared 2026-11-06 UTC before receipt of any candidate. Baseline is main
`3d4c7acde88ea1ebf2fff0d3009ad877d5a1bbd3`. This is a plan, not an implementation verdict.

## Candidate identity and independence

Record the supplied branch and full SHA, fetch read-only into a new candidate checkout,
verify identity before build and after review, and save evidence in a new subdirectory.
Do not modify product code/tests, push evidence, submit reviews, change Draft state,
merge or publish. Author logs are comparison material, not independent PASS evidence.
Any later fix requires a fresh final SHA and targeted retest followed by required checks.

## Storage and asynchronous copy

Snapshot every existing app key byte for byte using synthetic records, including progress,
lab, exploration, services, services-practice, research, notebook, live, canvas, nano-banana,
video-music and skills. Only the new chapter10 key and explicitly requested completion
change may change. Test chapter-only reset, cancel, whole-app reset and reload separately.
The existing whole-app reset clears completion only and retains chapter records.

Insert conspicuous synthetic free text into every offered text field and external-answer
area, make fixed changes, copy, retry, navigate and reload. Inspect all storage writes and
keys for the sentinel. Persist only whitelisted fixed data under the new key. No private
documents or credentials will be used. Test invalid JSON, valid JSON with wrong shapes,
unknown IDs, read denial, quota/write denial and remove denial. Notices must explain
temporary state and possible old-record return without claiming persistence/deletion success.

Control clipboard promises separately from UI. Test rejection, explicit retry, edit A→B→A,
theme/topic/step changes, retry, reset and unmount. Settle an older success and failure while
a newer request is pending, and in the same event turn as invalidation. Old callbacks must
not add success, restore old records, replace current feedback or clear new busy state.
Compare copied full text with the visible prompt; failed API calls do not earn success.
Mocked clipboard tests do not verify physical clipboard contents or cancellation of OS writes.

## Browser and accessibility matrix

Operate Chromium and WebKit at 1280/320/375/390 CSS pixels, light/dark, root font 100%/200%:
32 combinations. Include reduced-motion behavior, all steps and key evidence/compare states.
Measure viewport overflow and relevant element bounds, inspect representative PNG pixels,
and use keyboard Tab/Shift+Tab/Enter/Space/arrows on inputs and step/reset/copy controls.
Check visible focus, heading focus after step navigation, reset/cancel return, sensible
labels/status announcements, native controls and manual copy fallback. Do not infer visual
readability merely from scrollWidth or screen-reader support merely from ARIA.

identity, compare additions/deletions, run the candidate's required full suite and independent
sequence tests. Record all failures and harness errors separately; do not modify tests to fit.
Match final CI's SHA and status to raw evidence when available. Baseline raw CI log retrieval
is currently forbidden at the redirected Azure Blob URL; do not retry absent new evidence.

Recheck primary Google docs for Gemini app notebooks, standalone Gemini Notebook and old
NotebookLM naming; distinguish documented synchronization from verified account eligibility
and automatic Research-report/citation transfer. No Google login/OAuth/API/upload is in scope.

NOT_TESTED unless actually performed: real Google, real Safari/iPhone, Android device,
screen reader, physical clipboard, account eligibility, real document transfer, educational efficacy.
